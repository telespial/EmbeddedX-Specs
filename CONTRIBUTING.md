# Contributing to EmbeddedX

The EmbeddedX repository should remain architectural, platform-level, and relatively stable.

Detailed technical requirements for MRD, MDF, EIL, and AICS should usually be contributed to those repositories directly unless the change affects the platform as a whole.

## Preferred Contribution Types

* terminology alignment
* architecture clarification
* interoperability guidance
* ecosystem templates
* platform-level examples
* governance improvements

## What Usually Belongs Elsewhere

* detailed MRD structures
* detailed MDF structures
* detailed EIL runtime API rules
* detailed AICS schema rules
* implementation-specific runtime code
* vendor-specific examples that do not affect platform-level understanding

## Style Guidance

Keep contributions:

* clear
* technical
* concise
* compatible with existing terminology
* architectural rather than promotional
