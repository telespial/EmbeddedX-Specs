# EmbeddedX Repositories

## Official Repository Roles Within the EmbeddedX Platform

Proposed by: Richard Haberkern  
Contact: rmhaberkern@gmail.com  

Free for evaluation. Commercial use requires permission. See license.md for more information.

* * *

## 1. EmbeddedX

The umbrella platform repository.

Purpose:

* define philosophy
* define architecture
* define interoperability expectations
* point to sibling specifications
* provide templates and platform-level guidance

* * *

## 2. MRD

Machine Readable Datasheet specification repository.

Purpose:

* define structured hardware meaning
* define pins, registers, interfaces, constraints, and errata
* support machine-assisted firmware understanding

* * *

## 3. MDF

Model Definition Format specification repository.

Purpose:

* define model package structure
* define inputs and outputs
* define runtime assumptions
* support portable embedded model packaging

* * *

## 4. EIL

Embedded Intelligence Layer specification repository.

Purpose:

* define runtime integration behavior
* define advisory, anomaly, adaptive, and hybrid intelligence boundaries
* keep intelligence separate from deterministic firmware logic

* * *

## 5. AICS

AI Coding Specification repository.

Purpose:

* define constrained AI code generation
* define visible diffs and review expectations
* define validation and execution feedback expectations
* define how AI coding systems remain inspectable and bounded

* * *

## 6. Future Repository Direction

Optional future repositories may include:

* validators
* conformance
* converters
* examples
* reference implementations
* sdk-environment
* release-oriented modules such as security, runtime packaging, or generation engines
