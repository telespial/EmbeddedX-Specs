# EmbeddedX Governance

## Governance Notes for the EmbeddedX Platform Specification

Proposed by: Richard Haberkern  
Contact: rmhaberkern@gmail.com  

Free for evaluation. Commercial use requires permission. See license.md for more information.

* * *

## 1. Governance Goal

The platform repository should remain stable, architectural, and system-level.

* * *

## 2. What Belongs Here

This spec should focus on:

* philosophy
* architecture
* interoperability
* naming consistency
* platform-wide terminology
* repository relationships
* ecosystem-level templates

* * *

## 3. What Belongs in Sibling Repositories

Detailed technical rules for MRD, MDF, EIL, and AICS should stay in those repositories unless a change affects the platform as a whole.

* * *

## 4. Preferred Evolution Pattern

The platform repository should evolve more slowly than the detailed specification repositories.

This helps preserve a stable public frame for the ecosystem while still allowing technical iteration elsewhere.

* * *

## 5. Naming Discipline

Terms should be used consistently across the ecosystem. If a new term affects the platform as a whole, the umbrella repository should eventually define it.

* * *

## 6. Release Discipline

Platform-level release notes should summarize cross-repository changes only when those changes affect more than one layer.
